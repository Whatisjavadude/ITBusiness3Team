# 내 데스크 스튜디오 · 3D 배치 시뮬레이터

담당 범위: **사진 입력 → 벽면·책상 조건 조정 → 배치 변화** 1개 흐름, 구현·샘플 구분 표시

## 적용 방법

`js/features/studio.js`를 이 파일로 바꾸면 됩니다. 다른 파일은 고치지 않습니다.

- 외부 라이브러리 없이 Canvas로 3D를 그립니다. 설치·빌드·인터넷 없이 `index.html`만 열면 됩니다.
- `ui.js` 주석("시뮬레이터 담당자는 이 경계에서 구현을 교체")대로, 스튜디오 화면의 `D.scene()` 자리만 3D로 바꿨습니다. 프리셋·커뮤니티 화면은 계속 `D.scene()` SVG를 씁니다.
- 추가 스타일은 `studio.js` 안에서 `sim-` 접두사로만 넣습니다.

## 기존 화면에서 바뀐 곳

화면 구조(스튜디오 캔버스, 크기 입력 폼, 제품 목록, AI 어시스턴트, 사진 업로드)와 기존 버튼·동작은 그대로입니다.

| 위치 | 변경 |
|---|---|
| `.studio-canvas` | SVG 샘플 → 3D 캔버스. 라벨을 "3D 미리보기 · 실측 비율 (구현) · 제품 모양 단순화 (샘플)"로 |
| 크기 입력 폼 | 너비·깊이에 더해 책상 높이, 책상~뒷벽·옆벽 거리, 창문 위치, 벽 3면 켜기/끄기. 버튼 이름은 "조건 적용" |
| 패널 아래쪽 | 배치 점검 · 배치 변화(제품 선택, 회전, 자동 배치) · 변경 전·후 |
| 사진 업로드 | "📏 사진에서 책상 치수 재기" 버튼, 사진에서 읽은 색 결과 칸 |
| 상단 알약 | "배치 미리보기" → "3D 배치" |
| 화면 맨 위 제목 영역 | "YOUR SPACE, YOUR WAY / 나다운 공간을 만들어보세요 / 책상을 꾸미고…" 영역을 없앴습니다 |
| 패널 위쪽 | 진행 단계 줄(1. 사진 입력 → 2. 벽면·책상 조건 → 3. 배치 변화)과 '구현 실제 계산 · 샘플 시연용 가정' 범례 줄을 없앴습니다 |
| 크기 입력 폼 안내 | '입력값이 3D에 실측 비율로 반영됩니다 (구현) / 제품 깊이·높이는 가정값 (샘플)' 문구를 없앴습니다. 사진에서 잰 값 안내와 도면 벽 안내는 해당될 때만 나옵니다 |
| 패널 제목 줄 | 그 자리에 있던 **프리셋 불러오기 · 구성 저장** 버튼을 "나의 첫 번째 데스크 · 3D 배치 · 초기화" 줄로 옮겼습니다. 동작은 같습니다 |

## 흐름

| 단계 | 하는 일 | 구분 |
|---|---|---|
| 1 사진 입력 | 내 책상 사진 업로드·미리보기 | 구현 |
| | 사진에서 기준 물건·책상 양 끝을 클릭해 너비(·높이) 측정 → 3D 반영 | 구현 (원근 오차 있음) |
| | 스타일 사진 → 대표 색·가까운 스타일 → 3D 색 반영 | 구현 (색 기반) |
| 2 벽면·책상 조건 | 폼 값을 "조건 적용"하면 3D에 실측 비율로 반영, 맞지 않는 제품 수를 알림 | 구현 |
| 3 배치 변화 | 3D에서 끌어 옮기기, 회전, 규칙 기반 자동 배치, 변경 전·후 평면도와 바뀐 점 목록 | 구현 |

**배치 점검**(구현)
- 책상 밖으로 나간 제품 (몇 cm인지)
- 책상 뒤로 나가 벽에 닿는 경우 (책상~벽 거리 기준)
- 옆벽에 닿는 경우
- 제품끼리 겹침. 단, 모니터가 받침대 위에 완전히 올라가 있으면 정상으로 봄
- 남은 책상 면적 %
- 창문 관련 참고 안내: 모니터 뒤 창문은 눈부심, 조명과 창문이 같은 쪽이면 빛 쏠림. 일반 원칙에 따른 안내이고 정밀 계산은 아닙니다.

## data.js 기준으로 맞춘 점

- 제품 너비는 `data.js`의 `width`를 그대로 씁니다 (모니터 61, 램프 18, 키보드 32, 받침대 80cm).
- `shelf`(우드 모니터 받침대)는 책상 위 제품으로 처리합니다. 모니터를 위에 올릴 수 있고, 자동 배치도 모니터를 받침대 위에 올립니다.
- 책상·벽 색은 `D.scene()`의 스타일 색(내추럴·미니멀·크리에이티브)과 맞췄습니다.

## 샘플로 남은 부분

- 제품 깊이·높이: `data.js`에 없어서 `SAMPLE_DIMS`에 가정값을 넣었습니다. 데이터에 `depth`·`height`가 생기면 그 값을 먼저 씁니다.
- 제품 3D 모양: 상자 조합으로 단순화했습니다.

## 공유 상태와 다른 화면과의 관계

| 키 | 내용 |
|---|---|
| `D.state.room` | 책상 높이, 벽, 책상~벽 거리, 창문 |
| `D.state.layout` | 제품별 `{ x, z, rot }` (cm, 책상 가운데 기준) |

- 제품 화면·AI 어시스턴트에서 제품을 넣고 빼면, 새 제품은 빈 자리에 놓이고 빠진 제품의 위치는 지워집니다.
- 프리셋 적용으로 책상 크기가 바뀌면 새 크기에 맞춰 자동으로 다시 놓습니다. 이 화면의 폼으로 크기를 바꾼 경우는 그대로 두고 배치 점검에서 문제를 보여줍니다.
- "구성 저장" 프리셋에 `room`과 `layout`도 함께 저장합니다. 프리셋 담당이 적용할 때 이 두 값을 복사하면 배치까지 불러올 수 있습니다.


## 사진 → 3D 반영 [구현]

외부 AI 없이 브라우저 안에서 사진 픽셀의 색만 분석합니다. 사진은 서버로 보내지 않습니다.

| 사진 | 읽는 것 | 3D에서 바뀌는 것 |
|---|---|---|
| 내 책상 사진 | 사진 아래 가운데 = 책상 상판 색, 위쪽 = 벽 색 (그 영역에서 가장 많은 색) | 책상 상판 색, 벽 색 |
| 원하는 스타일 사진 | 대표 색 5개(k-means)와 비중. 따뜻한 기운이 있으면 내추럴, 무채색이면 미니멀, 차갑거나 색이 진하면 크리에이티브 | 벽·상판·다리·포인트(조명) 색, 스타일 버튼(내추럴·미니멀·크리에이티브) |

- 올리면 바로 반영됩니다. 사진 아래 결과 칸에서 읽은 색을 보고, 체크박스로 반영을 켜고 끌 수 있습니다.
- 우선순위: 스타일 사진(원하는 모습) > 책상 사진(지금 모습) > 기본 스타일 색. 3D 라벨에 "○○ 사진 색 반영 중"이 표시됩니다.
- 스타일 버튼을 직접 누르면 스타일 사진 반영은 꺼지고 버튼이 우선합니다. 체크를 끄면 원래 스타일로 돌아갑니다.
- 색 역할: 가장 밝은 색 = 벽, 가장 어두운 색 = 다리, 나머지 중 비중 큰 색 = 상판, 남은 색 중 가장 진한 색 = 포인트.
- 결과는 `D.state.room.deskPhoto`, `D.state.room.stylePhoto`에 저장되어 "구성 저장" 프리셋에도 들어갑니다.

### 책상 사진으로 치수 재기 [구현]

AI 자동 인식 없이 **기준 물건 비율**로 계산합니다.

1. 내 책상 사진을 올린 뒤 "📏 사진에서 책상 치수 재기"를 누르면 큰 창이 열립니다.
2. **기준 물건**(A4 용지 긴 변 29.7cm · 짧은 변 21cm · 신용카드 8.56cm · 직접 입력)의 양 끝을 클릭합니다.
3. **책상 너비**: 상판 왼쪽 끝과 오른쪽 끝을 클릭합니다.
4. **책상 높이 (선택)**: 바닥(다리 끝)과 상판 윗면을 클릭합니다.
5. "3D에 적용"을 누르면 너비(80~240cm)와 높이(60~110cm)가 크기 입력칸과 3D에 반영됩니다.

- 점은 끌어서 고칠 수 있고, 단계 버튼을 눌러 다시 찍을 수 있습니다. Esc나 바깥 클릭으로 닫힙니다. 새 사진을 올리면 점이 초기화됩니다.
- 계산식: 책상 길이 = (책상 양 끝 픽셀 거리 ÷ 기준 물건 픽셀 거리) × 기준 물건 길이
- 정확도: 기준 물건을 책상 앞 가장자리에 나란히 두고 정면에서 수평으로 찍으면 가장 정확합니다. 비스듬히 찍으면 원근 때문에 몇 cm 오차가 날 수 있어 "약 ○cm"로 표시합니다. 깊이는 원근 영향이 커서 재지 않고 직접 입력합니다.
- 반듯한 시험 사진(140×73cm 책상 + A4 용지)으로 재었을 때 너비 140cm, 높이 73cm가 그대로 나왔습니다.

**한계 (미연결):** 사진 속 가구 종류와 배치는 읽지 않습니다. 기준 물건 없이 자동으로 재거나 사물을 인식하려면 이미지 인식 AI API 연결이 필요합니다.

## 3D 크게 보기 [구현]

- 3D 화면 오른쪽 위 **⤢ 크게 보기** 버튼을 누르면 3D 화면만 브라우저 창을 거의 가득 채운 큰 창으로 뜹니다. 큰 창 배경은 어두운 남색이라 밝은 벽과 바닥이 잘 구분됩니다. 뒤 화면은 어둡게 가려지고 스크롤되지 않습니다.
- **원래 화면으로** 버튼, **Esc** 키, 바깥 어두운 곳 클릭 중 하나로 돌아옵니다.
- 같은 3D 화면을 키우는 방식이라 시점·선택한 제품·벽 도면 창이 그대로 유지됩니다. 큰 창 아래쪽에는 책상 크기와 조작 방법이 표시됩니다.
- 벽 도면 창 안에서 Esc를 누르면 도면 창이 먼저 닫히고, 한 번 더 누르면 원래 화면으로 돌아갑니다.
- 다른 메뉴로 이동하면 크게 보기는 자동으로 꺼집니다.
- 이전 버전의 '테두리 끌어 크기 조절'은 주변 화면 구조에 가려 의도대로 보이지 않아 이 기능으로 대체했습니다.

## 벽 도면 그리기 [구현]

- 3D 화면에서 **벽을 클릭**하면 그 벽의 도면 창(위에서 본 모습)이 3D 화면 위에 열립니다. 제목줄을 끌어 창을 옮길 수 있습니다.
- 도구는 **직선**과 **곡선** 두 가지뿐입니다. 도면을 클릭할 때마다 끝점에서 선이 이어지므로, 꺾이는 코너나 둥근 코너를 만들 수 있습니다.
- 곡선은 ◆ 손잡이를 끌어 휘는 정도를 바꿉니다. ● 점도 끌어 옮길 수 있습니다. 모든 점은 5cm 단위로 맞춰지고, 직선 옆에는 길이(cm)가 표시됩니다. 직선은 수평·수직에서 8° 안쪽이면 반듯하게 붙어 직각 코너를 만들기 쉽습니다.
- 그리는 즉시 3D에 반영됩니다. 편집 중인 벽은 주황색 테두리로 표시됩니다.

### 벽 목록 · 원하는 벽만 지우기
- 도면 창 맨 위에 세 벽이 칩으로 나옵니다. **이름**을 누르면 그 벽 도면으로 바뀌고(✎ = 도면을 고친 벽), **✕**를 누르면 그 벽만 지워집니다.
- 지운 벽은 **+ ○○ 세우기**로 다시 세울 수 있습니다. 아래 입력 폼의 벽 체크박스도 함께 바뀝니다.

### 벽이 겹치면 최근 벽만 남기기
- 선을 다 그린 순간(클릭·점 끌기를 놓았을 때·숫자 추가) 지금 그린 벽이 다른 벽을 **가로지르거나 같은 선 위에서 3cm 넘게 겹치면**, 겹친 **기존 벽이 지워지고** "오른쪽 벽이 방금 그린 뒷벽과 겹쳐서 지웠습니다" 알림이 잠깐 뜹니다.
- 코너처럼 끝점끼리 맞닿거나, 한 벽의 끝이 다른 벽에 붙는 T자 연결은 겹침으로 보지 않습니다.
- '+ 세우기'로 다시 세운 벽이 기존 벽과 겹쳐도 같은 규칙으로 기존 벽이 지워집니다.

### 되돌리기와 초기화
- **되돌리기**는 내가 그린 선만 하나씩 지웁니다. 아무것도 고치지 않은 처음 벽(과 처음 벽의 선)은 되돌리기로 사라지지 않고 "처음부터 있던 벽은 되돌리기로 지워지지 않아요" 알림만 나옵니다.
- **새로 그리기**: 이 벽을 비우고 시작점부터 다시 그립니다.
- **초기화 · 이 벽**: 이 벽만 처음 직선 벽(거리 입력값 기준)으로 되돌립니다.
- **초기화 · 모든 벽**: 세 벽의 도면을 모두 지우고 처음 상태(뒷벽·오른쪽 벽 켜짐, 왼쪽 벽 꺼짐)로 되돌립니다. 책상과 제품 배치는 그대로입니다. (패널 제목 줄의 '초기화'는 기존처럼 전체 초기화)

### 직선 벽 숫자로 만들기
- 도면 아래 **직선 숫자로 추가**에 길이(cm, 5~1000)와 방향(→ 오른쪽 · ↓ 앞쪽 · ← 왼쪽 · ↑ 뒤쪽 · 각도 입력)을 넣고 **추가**(또는 Enter)를 누르면 끝점에서 직선이 이어집니다.
- 각도는 0° = 오른쪽, 90° = 앞쪽(책상 쪽)입니다. 시작점이 없으면 그 벽의 처음 시작점에서 시작합니다. 숫자로 만든 선도 겹침 규칙과 되돌리기가 똑같이 적용됩니다.

### 그 밖
- 배치 점검에 "책상이 ○○ 도면과 겹침", "제품: ○○에 닿음"이 추가되고, 변경 전·후에 "○○: 도면 변경"이 나옵니다.
- 창문은 그 벽에서 가장 긴 곧은 부분(100cm 이상)의 책상 쪽 위치에 놓입니다.
- 도면을 그린 벽은 "책상~뒷벽/옆벽 거리" 입력값 대신 도면을 따릅니다.
- 도면은 `D.state.room.paths`에 `{ start, segs: [{ type: 'line', to } | { type: 'curve', c, to }], base }` 형태(cm)로 저장됩니다. `base`는 되돌리기로 지우지 않는 처음 벽의 선 개수입니다. "구성 저장" 프리셋에도 함께 들어갑니다.

| 좌클릭 드래그 (빈 곳·벽) | 카메라 위치 이동. 화면이 마우스를 따라 움직입니다 |
| 우클릭 드래그 | 카메라는 그 자리에 두고 시점 돌리기. 오른쪽으로 끌면 오른쪽, 위로 끌면 위를 봅니다 |
| 우클릭을 누른 채 W·A·S·D / Q·E | 앞·왼쪽·뒤·오른쪽 / 아래·위로 날아다니기 (Shift: 더 빠르게) |
| Alt + 좌클릭 드래그 | 바라보는 점을 중심으로 돌기 (이전 버전의 회전 방식) |
| 가운데 버튼 드래그 | 카메라 위치 이동 |
| 휠 | 바라보는 방향으로 앞뒤 이동. 가까이 가면 계속 앞으로 들어갑니다 |
| F | 선택한 제품을 화면 가운데로 (선택이 없으면 책상 전체) |
| 빈 곳 더블클릭 | 시점 처음으로 |
| 좌클릭 드래그 (제품) | 제품 이동 · 선택 후 방향키 1cm(Shift 5cm), R 회전, Esc 선택 해제 |
| 벽 클릭 (끌지 않고) | 벽 도면 창 |

- 3D 화면 왼쪽 아래에 짧은 조작 안내가 보이고, 크게 보기에서는 전체 안내가 나옵니다.
- 3D 화면 위에서는 브라우저 우클릭 메뉴가 뜨지 않습니다.
- 카메라는 바닥 아래로 내려가지 않습니다. 방 안으로 들어가도 카메라 앞에서 면을 잘라 그려서 바닥과 벽이 사라지지 않습니다.
- 책상 크기를 바꾸거나 초기화하면 시점도 처음으로 돌아갑니다.

## 확인한 것

- 제목 영역 제거와 버튼 이동, 처음 벽에서 되돌리기(사라지지 않음), 숫자로 직선 추가(방향·각도·Enter), 겹친 벽 자동 삭제와 알림·체크박스 동기화, 벽 목록의 ✕ 지우기·다시 세우기, 이 벽/모든 벽 초기화, 겹침 판정(가로지름·같은 선 겹침은 지움 / 코너·T자·평행은 유지)을 확인했습니다. 기존 카메라 조작·크게 보기·벽 도면 회귀 테스트도 통과했고 스크립트 오류는 없었습니다.

팀의 `index.html`, `data.js`, `ui.js`, `app.js`, `assistant.js`, `presets.js`, `products.js`와 합쳐 Chromium으로 확인했습니다. 확인한 흐름은 사진 업로드 → 조건 적용 → 제품 추가 → 자동 배치 → 드래그·회전 → 변경 전·후, 그리고 프리셋 적용과 AI 어시스턴트 버튼까지입니다. 스크립트 오류는 없었습니다.

팀 CSS(`tokens.css`, `shell.css`, `features.css`, `chat-ai.css`)를 넣은 상태에서 화면을 확인했습니다. 팀 CSS 파일은 고치지 않았고, 여백·버튼 크기 조정은 모두 `studio.js` 안의 `sim-` 스타일로 했습니다.

### 3D 화면 크기와 처음 시점
- 팀 CSS의 `.studio-canvas`(높이 405px) 칸에 3D가 꽉 차도록 맞췄습니다. 전에는 3D가 칸보다 길게 그려져 아래쪽(책상 다리·바닥)이 잘려 보였습니다.
- 처음 시점은 책상 정면에서 살짝 내려다보는 각도로 바꿨습니다(방향 −0.04, 높이각 0.24, 거리 = 책상 크기×1.0+25cm, 바라보는 점은 책상 상판 22cm 위). 더블클릭·초기화·크기 변경 때도 이 시점으로 돌아갑니다.
- 조작 안내는 왼쪽 위로 옮겨 아래쪽 책상 치수 표시와 겹치지 않게 했고, 팀 마크업의 '3D 미리보기 · 실측 비율 (구현)' 라벨은 가렸습니다.

### 여백 정리
- 배치 점검 · 배치 변화 · 변경 전·후 칸에 좌우 18px, 위아래 14px 여백을 넣어 패널 가장자리에 붙지 않게 했습니다 (패널 제목 줄·입력 폼과 같은 18px).
- 벽 켜기/끄기 체크박스가 입력칸 너비(86px)를 물려받아 벌어지던 것을 체크박스 크기로 맞췄습니다.
- 패널 제목 줄의 프리셋 불러오기 · 구성 저장, 크게 보기, 벽 도면 창, 치수 재기 버튼을 주변 버튼 크기에 맞춰 줄였습니다.
