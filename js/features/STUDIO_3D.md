# 내 데스크 스튜디오 · 3D 배치 시뮬레이터

담당 범위: **사진 입력 → 벽면·책상 조건 조정 → 배치 변화** 1개 흐름, 구현·샘플 구분 표시

## 적용 방법

`js/features/studio.js`를 이 파일로 바꾸면 됩니다. 다른 파일은 고치지 않습니다.

- 외부 라이브러리 없이 Canvas로 3D를 그립니다. 설치·빌드·인터넷 없이 `index.html`만 열면 됩니다.
- `ui.js` 주석("시뮬레이터 담당자는 이 경계에서 구현을 교체")대로, 스튜디오 화면의 `D.scene()` 자리만 3D로 바꿨습니다. 프리셋·커뮤니티 화면은 계속 `D.scene()` SVG를 씁니다.
- 추가 스타일은 `studio.js` 안에서 `sim-` 접두사로만 넣습니다.

## 기존 화면에서 바뀐 곳

화면 구조(제목, 스튜디오 캔버스, 크기 입력 폼, 제품 목록, AI 어시스턴트, 사진 업로드)와 기존 버튼·동작은 그대로입니다.

| 위치 | 변경 |
|---|---|
| `.studio-canvas` | SVG 샘플 → 3D 캔버스. 라벨을 "3D 미리보기 · 실측 비율 (구현) · 제품 모양 단순화 (샘플)"로 |
| 크기 입력 폼 | 너비·깊이에 더해 책상 높이, 책상~뒷벽·옆벽 거리, 창문 위치, 벽 3면 켜기/끄기. 버튼 이름은 "조건 적용" |
| 패널 위쪽 | 진행 단계 한 줄(1 사진 입력 → 2 벽면·책상 조건 → 3 배치 변화)과 구현/샘플 범례 |
| 패널 아래쪽 | 배치 점검 · 배치 변화(제품 선택, 회전, 자동 배치) · 변경 전·후 |
| 사진 업로드 | "사진으로 책상 크기 추정 (샘플)" 버튼 |
| 상단 알약 | "배치 미리보기" → "3D 배치" |

## 흐름

| 단계 | 하는 일 | 구분 |
|---|---|---|
| 1 사진 입력 | 내 책상 사진 업로드·미리보기 | 구현 |
| | 사진으로 크기 추정 → 예시 값 120×60cm 입력 | **샘플** |
| | 스타일 사진 미리보기 | **샘플** (분석 미연결) |
| 2 벽면·책상 조건 | 폼 값을 "조건 적용"하면 3D에 실측 비율로 반영, 맞지 않는 제품 수를 알림 | 구현 |
| 3 배치 변화 | 3D에서 끌어 옮기기, 회전, 규칙 기반 자동 배치, 변경 전·후 평면도와 바뀐 점 목록 | 구현 |

**배치 점검**(구현)
- 책상 밖으로 나간 제품 (몇 cm인지)
- 책상 뒤로 나가 벽에 닿는 경우 (책상~벽 거리 기준)
- 옆벽에 닿는 경우
- 제품끼리 겹침. 단, 모니터가 받침대 위에 완전히 올라가 있으면 정상으로 봄
- 남은 책상 면적 %
- 창문 관련 참고 안내: 모니터 뒤 창문은 눈부심, 조명과 창문이 같은 쪽이면 빛 쏠림. 일반 원칙에 따른 안내이고 정밀 계산은 아닙니다.

## data.js 기준으로 맞춘 점

- 제품 너비는 `data.js`의 `width`를 그대로 씁니다 (모니터 61, 램프 18, 키보드 32, 받침대 80cm).
- `shelf`(우드 모니터 받침대)는 책상 위 제품으로 처리합니다. 모니터를 위에 올릴 수 있고, 자동 배치도 모니터를 받침대 위에 올립니다.
- 책상·벽 색은 `D.scene()`의 스타일 색(내추럴·미니멀·크리에이티브)과 맞췄습니다.

## 샘플로 남은 부분

- 제품 깊이·높이: `data.js`에 없어서 `SAMPLE_DIMS`에 가정값을 넣었습니다. 데이터에 `depth`·`height`가 생기면 그 값을 먼저 씁니다.
- 제품 3D 모양: 상자 조합으로 단순화했습니다.
- 사진 크기 추정: 예시 값만 넣습니다.

## 공유 상태와 다른 화면과의 관계

| 키 | 내용 |
|---|---|
| `D.state.room` | 책상 높이, 벽, 책상~벽 거리, 창문 |
| `D.state.layout` | 제품별 `{ x, z, rot }` (cm, 책상 가운데 기준) |

- 제품 화면·AI 어시스턴트에서 제품을 넣고 빼면, 새 제품은 빈 자리에 놓이고 빠진 제품의 위치는 지워집니다.
- 프리셋 적용으로 책상 크기가 바뀌면 새 크기에 맞춰 자동으로 다시 놓습니다. 이 화면의 폼으로 크기를 바꾼 경우는 그대로 두고 배치 점검에서 문제를 보여줍니다.
- "구성 저장" 프리셋에 `room`과 `layout`도 함께 저장합니다. 프리셋 담당이 적용할 때 이 두 값을 복사하면 배치까지 불러올 수 있습니다.


## 3D 크게 보기 [구현]

- 3D 화면 오른쪽 위 **⤢ 크게 보기** 버튼을 누르면 3D 화면만 브라우저 창을 거의 가득 채운 큰 창으로 뜹니다. 뒤 화면은 어둡게 가려지고 스크롤되지 않습니다.
- **원래 화면으로** 버튼, **Esc** 키, 바깥 어두운 곳 클릭 중 하나로 돌아옵니다.
- 같은 3D 화면을 키우는 방식이라 시점·선택한 제품·벽 도면 창이 그대로 유지됩니다. 큰 창 아래쪽에는 책상 크기와 조작 방법이 표시됩니다.
- 벽 도면 창 안에서 Esc를 누르면 도면 창이 먼저 닫히고, 한 번 더 누르면 원래 화면으로 돌아갑니다.
- 다른 메뉴로 이동하면 크게 보기는 자동으로 꺼집니다.
- 이전 버전의 '테두리 끌어 크기 조절'은 주변 화면 구조에 가려 의도대로 보이지 않아 이 기능으로 대체했습니다.

## 벽 도면 그리기 [구현]

- 3D 화면에서 **벽을 클릭**하면 그 벽의 도면 창(위에서 본 모습)이 3D 화면 위에 열립니다. 제목줄을 끌어 창을 옮길 수 있습니다.
- 도구는 **직선**과 **곡선** 두 가지뿐입니다. 도면을 클릭할 때마다 끝점에서 선이 이어지므로, 꺾이는 코너나 둥근 코너를 만들 수 있습니다.
- 곡선은 ◆ 손잡이를 끌어 휘는 정도를 바꿉니다. ● 점도 끌어 옮길 수 있습니다. 모든 점은 5cm 단위로 맞춰지고, 직선 옆에는 길이(cm)가 표시됩니다. 직선은 수평·수직에서 8° 안쪽이면 반듯하게 붙어 직각 코너를 만들기 쉽습니다.
- 버튼: 되돌리기(마지막 선 지우기) · 새로 그리기(벽을 지우고 시작점부터) · 기본 직선 벽(도면을 지우고 거리 입력값으로 되돌림)
- 그리는 즉시 3D에 반영됩니다. 편집 중인 벽은 주황색 테두리로 표시됩니다.
- 배치 점검에 "책상이 ○○ 도면과 겹침", "제품: ○○에 닿음"이 추가되고, 변경 전·후에 "○○: 도면 변경"이 나옵니다.
- 창문은 그 벽에서 가장 긴 곧은 부분(100cm 이상)의 책상 쪽 위치에 놓입니다.
- 도면을 그린 벽은 "책상~뒷벽/옆벽 거리" 입력값 대신 도면을 따릅니다.
- 도면은 `D.state.room.paths`에 `{ start, segs: [{ type: 'line', to } | { type: 'curve', c, to }] }` 형태(cm)로 저장됩니다. "구성 저장" 프리셋에도 함께 들어갑니다.

## 조작

- 빈 곳 드래그: 시점 회전 · 휠: 확대/축소 · 제품 드래그: 이동 · 벽 클릭: 벽 도면 창 · ⤢ 버튼: 크게 보기 (Esc로 돌아옴)
- 3D 화면을 클릭한 뒤 방향키: 1cm 이동 (Shift 누르면 5cm), R: 90° 회전, Esc: 선택 해제

## 확인한 것

팀의 `index.html`, `data.js`, `ui.js`, `app.js`, `assistant.js`, `presets.js`, `products.js`와 합쳐 Chromium으로 확인했습니다. 확인한 흐름은 사진 업로드 → 조건 적용 → 제품 추가 → 자동 배치 → 드래그·회전 → 변경 전·후, 그리고 프리셋 적용과 AI 어시스턴트 버튼까지입니다. 스크립트 오류는 없었습니다.

`styles/` 폴더의 CSS 파일은 받지 못해서 임시 스타일로 확인했습니다. 실제 팀 CSS에서 줄 간격이나 버튼 모양은 조금 다르게 보일 수 있습니다.
