# 팀 작업 시작 안내

## 가장 먼저 할 일

1. 저장소 초대를 받아 `index.html`을 열고 공통 화면을 확인합니다.
2. 카카오톡에서 담당 영역을 정합니다. 아래 A~D는 분담 제안이며 사람 이름을 지정한 것은 아닙니다.
3. `git pull`로 최신 파일을 받고 기능 브랜치를 만듭니다.
4. 본인 영역을 제작한 뒤 변경 화면과 확인 결과를 Pull Request에 남깁니다.
5. 공통 담당이 화면·연결을 확인하고 합칩니다.

## 작업 분담 제안

공통 담당은 요청자의 역할입니다. 다른 담당자 수는 현재 팀 구성에 맞게 조정합니다.

| 담당 | 우선순위·작업 | 주로 수정할 파일 | 완료 기준 |
|---|---|---|---|
| 공통 담당 | 공통 스타일·페이지 구조·통합 | `index.html`, `styles/tokens.css`, `styles/shell.css`, `js/app.js`, `js/ui.js`, `js/data.js` | 화면 틀과 기능 연결이 일관됨 |
| A | P1-A 시뮬레이터 샘플 | `js/features/studio.js` | 사진 입력 → 벽면/책상 조건 조정 → 배치 변화 1개 흐름. 구현·샘플 구분 표시 |
| B | P1-B AI 대화 샘플 | `js/features/assistant.js` | 조건 추천 → 추가 요구 → 구성 변경. 국내 가격 비교 결과는 목업으로 설명 |
| C | P2 프리셋·비교 → P3 제품 | `js/features/presets.js`, `products.js` | 저장·불러오기·2안 비교·제품 상세 목업 연결 |
| D | P4 로드맵 → P5 커뮤니티 | `js/features/roadmap.js`, `community.js` | 구매 순서·할인 안내, 피드·게시물 목업 연결 |

A와 B는 같은 샘플 시나리오를 맞춰야 합니다. 예: “140×70cm 책상, 예산 30만원 → 미니멀 구성 → 조명을 추가하면 어떻게 달라지는가”. 구현 데이터나 판정식을 사실처럼 보여주지 않고 시연 데이터라고 표시합니다.

`styles/features.css`는 현재 기능별 접두사로 구분되어 있습니다. 동시에 큰 수정을 할 때는 자기 기능의 CSS를 `styles/studio.css`처럼 분리하고, 공통 담당이 `index.html`에 연결합니다. 다른 담당자의 영역을 통째로 덮어쓰지 않습니다.

## 브랜치·PR 규칙

예시:

```sh
git switch main
git pull --ff-only
git switch -c feature/studio-sample
# 본인 파일 수정 후
git add js/features/studio.js styles/features.css
git commit -m "feat: add studio sample interaction"
git push -u origin feature/studio-sample
```

GitHub에서 `Compare & pull request`로 PR을 엽니다. 브랜치는 `feature/ai-sample`, `feature/presets-compare`, `feature/roadmap-mock`처럼 작업 단위를 드러내면 됩니다. 샘플 명령의 파일 목록은 실제 변경한 파일로 바꿉니다.

- PR 하나에는 하나의 사용자 흐름을 담습니다.
- 공통 파일 수정이 필요하면 카카오톡에 파일명·이유를 먼저 공유합니다.
- 색상·폰트·메뉴를 개인 취향으로 따로 바꾸지 않습니다.
- 화면 캡처, 확인한 동작, 남은 목업 영역을 PR에 적습니다.
- 완료되지 않은 기능도 Draft PR로 공유할 수 있습니다.
- 민감한 자료·API 키·실사용자 사진을 저장소에 추가하지 않습니다.
- 배포 설정은 추가하지 않습니다.

## 기능별 완료 체크

- [ ] 기존 `index.html`에서 해당 기능으로 이동된다.
- [ ] 공통 메뉴·버튼·색상을 재사용한다.
- [ ] 핵심 클릭 흐름에 끊긴 버튼이 없다. 미구현 버튼은 상태를 분명히 표시한다.
- [ ] 기본·로딩·비어 있음·오류 화면을 확인했다.
- [ ] 새로고침 시 초기화되는 데이터와 실제 동작을 구분했다.
- [ ] 샘플 가격·추천·적합도를 사실로 표시하지 않았다.
- [ ] 1440px 화면과 좁은 화면에서 가로 넘침이 없다.
- [ ] 본인 변경으로 다른 메뉴가 깨지지 않는다.
- [ ] 실제 AI·3D·API 연결이 필요한 잔여 작업을 별도 적었다.

이 체크는 팀 내부의 기능 검토용입니다. 상위 ITBusiness 프로젝트의 승인 게이트나 검증 PASS를 대신하지 않습니다.

## 저장소 초대

저장소 소유자가 GitHub의 저장소 **Settings → Collaborators/Manage access**에서 팀원의 정확한 GitHub ID를 확인하고 초대합니다. 비공개 저장소는 초대를 수락한 계정에서 접근합니다. 이번 준비에서는 팀원 초대나 카카오톡 메시지를 발송하지 않았습니다.
