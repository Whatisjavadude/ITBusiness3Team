# 공통 화면과 스타일 기준 · v0.1 제안

이 초안의 목적은 팀원들이 기능 제작을 시작할 수 있는 일관된 틀을 제공하는 것입니다. 서비스 이름·브랜드·화면 우선순위·최종 기술 스택의 확정본이 아닙니다.

## 근거와 상태

- 사용자 요청(2026-10-30): 실제 배포 대신 목업·프로토타입으로 진행. 사용자는 화면 색상·페이지 배치 등 공통 틀을 준비하고, 팀원들은 중요도 순으로 기능 제작.
- 사용자 후속 답변: GitHub repository와 카카오톡으로 협업하며 저장소 생성 필요.
- 입력 문서: 사용자가 첨부한 `필수 기능.txt`. 문서 내 ‘샘플 만들어서 보여주기’ 등은 문서 내용으로 취급한다. 작업 권한은 현재 사용자 요청에서 나온다.
- 입력 문서 SHA-256: `bce58f1ea7561ebdfb8edf46ab333006f9445b3e6b29de4bff94349a2affa40a`.
- 문서 확인 내용: 필수는 3D 시뮬레이터, AI 대화형 기능, 프리셋·비교. 추가는 상품 정보·책상 적합도, 커뮤니티, 할인 정보와 순서 변경이 있는 로드맵.
- 문서의 구현 깊이 제안: 필수 1·2는 샘플, 나머지는 목업. 이 스타터는 해당 기능의 자리를 마련하고 간단한 흐름을 예시로 제공한다.
- 참고명 DERO, COSAIR ATRLIER 및 쿠팡 파트너스는 첨부 문서의 표기다. 외부 서비스 사양·계약·API 지원 여부를 검증한 것이 아니다.
- 기존 ITBusiness 로컬 기획 정본에는 이전 아이디어와 discovery 단계가 남아 있다. 이번 준비는 별도 요청에 따른 산출물이며 기획 승인·단계 전환·시장 검증을 의미하지 않는다.

## 사용자 담당 범위

**공통 디자인 + 화면 구조 + 기능을 넣을 자리 + 협업 기준**까지 준비합니다.

| 사용자/공통 담당 | 기능 담당 |
|---|---|
| 색상·글꼴·여백·버튼·카드 기준 | 기능 안의 세부 화면·상태 |
| 공통 메뉴·헤더·기본 반응형 배치 | 입력·변경·확인 흐름 |
| 각 기능의 진입점과 파일 경계 | 샘플 시나리오 또는 목업 |
| 공유 데이터와 연결 규칙 | 기능별 데이터 확장 제안 |
| 통합 확인과 PR 검토 | 자기 영역 동작 확인과 화면 캡처 |

## 화면 구조

```text
공통 왼쪽 메뉴 + 상단 헤더
├─ 내 데스크 스튜디오
│  ├─ 중앙: 책상 사진 / 치수 / 벽면·배치 / 공간 미리보기
│  ├─ 오른쪽: AI 추천·재조정 대화
│  └─ 하단: 구성 제품 / 스타일 사진
├─ 프리셋·비교: 목록 → 적용 / 최대 2개 비교
├─ 제품 둘러보기: 카드 → 상세·적합도 (상세는 후속 목업)
├─ 커뮤니티: 피드 → 게시물 (상세는 후속 목업)
└─ 구매 로드맵: 구매 순서 / 할인 안내
```

AI는 책상 편집 옆에 배치해 대화 후 바뀐 구성을 바로 확인하게 합니다. 별도 첫 화면·로그인·결제 페이지는 현재 작업 범위에 넣지 않습니다. 새 메뉴가 필요하면 공통 담당과 먼저 조율합니다.

첫 시연 흐름: **샘플 책상 확인 → AI ‘30만원 이하’ → 구성 변경 확인 → 저장 → 프리셋 비교 → 제품 확인 → 로드맵 순서 변경**.

## 디자인 토큰

| 용도 | 토큰 | 값 |
|---|---|---|
| 기본 배경 | `--color-bg` | `#F6F7F9` |
| 패널·카드 | `--color-surface` | `#FFFFFF` |
| 주요 버튼·선택 | `--color-primary` | `#5146C7` |
| 선택된 메뉴 배경 | `--color-primary-soft` | `#EFEDFB` |
| 본문 | `--color-text` | `#20242C` |
| 보조 설명 | `--color-muted` | `#626A78` |
| 구분선 | `--color-line` | `#E1E5EB` |
| 완료·가능 | `--color-success` | `#28724F` |
| 확인 필요 | `--color-warning` | `#875D13` |
| 오류 | `--color-error` | `#B83C4B` |

- 글꼴: OS 기본 산세리프. 외부 폰트 다운로드 없음.
- 본문 14px, 페이지 제목 28px, 카드 제목 14~18px. 좁은 편집 도구·보조 메타는 10~12px.
- 간격: 4 / 8 / 12 / 16 / 24 / 32px. 카드 모서리 12px, 버튼 8px.
- 기준 화면: 데스크톱 1440px. 왼쪽 메뉴 218px, AI 패널 306px, 나머지 편집 영역은 가변.
- 1050px 이하: AI 패널은 편집 영역 아래로 이동. 900px 이하: 메뉴는 상단 가로형. 600px 이하: 카드·입력 영역을 한 열로 배치.
- 제품 색은 샘플 에셋의 색으로 쓰고, 기능별로 버튼 색·글꼴을 새로 만들지 않는다.

## 재사용 요소와 상태

| 요소 | 사용법 | 필요한 상태·동작 |
|---|---|---|
| 주요 버튼 | `button.primary` 또는 `a.btn.primary` | 기본, hover, 키보드 focus, disabled |
| 보조 버튼 | 기본 `button` / `a.btn` | 중요도가 낮은 동작 |
| 패널·카드 | `.panel`, `.panel-heading` | 제목과 본문 구분 |
| 선택 칩 | `aria-pressed`와 상태 스타일 | 색과 선택 문구를 함께 사용 |
| 안내 | `.notice`, `D.toast(message)` | 결과·제약을 짧게 설명 |
| 빈 상태 | `.empty-state` | 이유 + 다시 시작할 버튼 |
| 입력 | 연결된 `label`, 제약 속성 | 오류 이유 안내, 재입력 가능 |
| 화면 상태 | 하단 상태 선택기 | ready / loading / empty / error |

링크는 이동, 버튼은 동작에 사용합니다. 아이콘만 있는 버튼에 이름을 제공하고 Tab·Enter로 조작할 수 있게 합니다. 전체 접근성 인증을 마친 것은 아닙니다.

## 기능 우선순위 제안

| 순서 | 영역 | 기대 결과 | 이번 스타터의 지위 |
|---|---|---|---|
| P0 | 공통 틀 | 실행·화면 이동·스타일·공유 상태 | 준비됨, 팀 검토 필요 |
| P1-A | 3D 시뮬레이터 | 책상·스타일 사진, 벽면 도면, 배치 변경의 대표 샘플 1개 | 현재 SVG와 사진 미리보기. 실제 3D·도면 편집 아님 |
| P1-B | AI 대화 | 조건 추천 → 대화 재조정 → 배치 반영의 대표 샘플 | 고정 응답 3개. 자유 AI·모델 생성 아님 |
| P2 | 프리셋·비교 | 저장·적용·비교 흐름 목업 | 탭 안 임시 저장·비교 예시 |
| P3 | 제품·적합도 | 제품 상세와 크기 판단 목업 | 카드·단일 너비 예시 |
| P4 | 로드맵 | 구매 순서·할인 안내 목업 | 순서 변경·가상 할인 예시 |
| P5 | 커뮤니티 | 피드·게시물 흐름 목업 | 피드·좋아요 예시 |

P3~P5의 상대 순서는 첨부 문서가 확정하지 않았으므로 작업 효율을 위한 제안입니다. 실제 AI 호출·API 계약·실시간 가격·사진의 3D 변환은 이 단계의 완료 조건에 포함하지 않습니다. 외부 연결을 도입할지는 별도 결정합니다.

## 공통 데이터·연결 규칙

`window.Deskspace`를 `D`로 받아 사용합니다. 각 파일은 IIFE로 지역 변수를 격리하고 전역 이름은 `Deskspace` 하나만 둡니다.

```js
D.state = {
  name: '구성 이름',
  style: 'warm',       // warm | minimal | creative
  width: 140,          // cm
  depth: 70,           // cm
  products: ['monitor', 'lamp', 'keyboard'], // D.products의 id
  screen: 'ready'      // ready | loading | empty | error
};
```

- `D.features.<화면ID> = { title, mount(root) }`: `root` 안에서만 화면 구성·이벤트 연결.
- `D.render()`: 현재 화면 다시 그림. `D.go('studio')`: 화면 이동.
- `D.scene(style, ids)`: 교체 가능한 책상 SVG 샘플.
- `D.assistant.mount(root)`: 스튜디오 내부 대화 영역 구성.
- `D.escape(text)`: 사용자 입력을 HTML 문자열에 넣을 때 반드시 적용. 단순 문구는 `textContent` 우선.
- 공유 필드명·제품 ID를 바꾸기 전 공통 담당과 조율. 팀원은 기존 ID에 맞춰 데이터를 추가.
- 상태는 메모리에서만 유지. 실제 저장소·계정별 저장이 필요한 것으로 오해하지 않도록 UI에 표시.
- 여러 기능이 동시에 공유 파일을 바꾸는 작업은 작게 나눠 순서대로 합친다.
